# Contributing to wasm-app-enclave-verifier

Thank you for your interest in contributing!  This is a small, single-purpose
WASM Component — please keep it that way.

## Getting Started

1. **Fork** the repository and clone your fork.
2. Install the toolchain:
   ```bash
   rustup target add wasm32-wasip1
   cargo install cargo-component
   ```
3. Build:
   ```bash
   cargo component build --release
   ```

## Project Structure

| Path | Description |
|------|-------------|
| `wit/world.wit` | The `enclave-verifier` world — public API surface. |
| `wit/deps/enclave-os/` | A pinned copy of the Enclave OS SDK WIT (must stay in sync with the runtime). |
| `src/lib.rs` | The whole implementation — assembles a `RatlsPolicy` and calls `https::fetch`. |
| `src/bindings.rs` | Auto-generated by `cargo component build` (gitignored). |

## Making Changes

- Keep the surface tiny — this project deliberately exports a **single**
  function.  New verification options should be added as fields on
  `verify-request`, never as new exports.
- Mirror any new RA-TLS field on `verify-request` to the matching field on
  `https::RatlsPolicy` so the result is forwarded byte-for-byte to the
  egress client.
- Map any new well-known host error string to a structured `error-code`
  in `classify()` — keep `other` as the catch-all.
- Run `cargo component build --release` and confirm the artifact size
  has not regressed significantly.
- Follow the existing code style — `cargo fmt`, no clippy warnings.

## Updating the Enclave OS WIT dependency

When the host adds a new field on `https::request` or a new variant on
`https::ratls-policy`, refresh the pinned copy:

```bash
cp ../../enclave-os/enclave-os-mini/crates/enclave-os-wasm/sdk/wit/enclave-os.wit \
   wit/deps/enclave-os/enclave-os.wit
cargo component build --release
```

The bindings are regenerated automatically.

## Submitting a Pull Request

1. Create a feature branch from `main`:
   ```bash
   git checkout -b my-feature
   ```
2. Make your changes and commit (signed commits are required).
3. Push to your fork and open a Pull Request against `main`.
4. Describe what you changed and why, and link to the upstream Enclave OS
   change if you are reacting to a WIT update.

## Reporting Issues

Please [open an issue](https://github.com/Privasys/wasm-app-enclave-verifier/issues)
with:

- A clear description of the problem or suggestion.
- The host TEE platform you are testing against (SGX or TDX, mini or virtual).
- The exact `verify-request` that triggered the issue (redact secrets).
- The `verify-result` you got back.

Security issues — please **do not** file them publicly. See [SECURITY.md](SECURITY.md).
